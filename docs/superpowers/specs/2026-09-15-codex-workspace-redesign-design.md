# Codex형 Code Atlas 작업 공간 재설계

작성일: 2026-09-15  
상태: 구현 전 승인 설계  
선택안: B — 대화 + 근거 검사기

## 1. 목표

Code Atlas의 첫 화면을 통계 대시보드에서 분석 대화 작업 공간으로 바꾼다. 사용자는 저장소, 커밋 또는 PR을 선택하고 중앙 흐름에서 “왜 바뀌었는지”, “무엇이 바뀌었는지”, “어디에 영향이 있는지”를 순서대로 읽는다. 근거의 원문과 코드 관계는 오른쪽 검사기에서 확인한다.

Git 수집, 로컬 소스 분석, OneDev PR 조회, LLM 어댑터와 데이터 저장 구조는 유지한다. 이번 변경의 중심은 정보 구조와 상호작용이며 분석 결과의 의미를 바꾸지 않는다.

## 2. 제품 원칙

1. 분석 단위 하나를 하나의 작업 대화처럼 보여준다.
2. 결론을 먼저 읽고 필요한 근거만 펼친다.
3. 기록, 코드 사실, 정적 관계, 추정을 시각적으로 분리한다.
4. 정적 관계 지도는 노출하지 않고 설명과 검사기에만 활용한다.
5. 화면을 닫았다가 다시 열어도 저장된 질문과 답변을 이어서 읽을 수 있다.

## 3. 화면 구조

```text
┌────────────────┬──────────────────────────────────┬──────────────────┐
│ 저장소 탐색     │ 현재 분석 작업                    │ 근거 검사기       │
│                │                                  │                  │
│ + 새 분석       │ 제목 / ref / 다시 분석            │ 기록된 이유       │
│ 저장소 검색     ├──────────────────────────────────┤ 코드 변경         │
│                │ Git 스냅샷 이벤트                  │ 영향 관계         │
│ 프로젝트        │ 변경 스토리 이벤트                │ 확인 필요         │
│  codeatlas      │ 프로젝트 영향 이벤트              │                  │
│  cupas          │ 질문과 답변 이벤트                │ 선택 근거 상세     │
│                │                                  │                  │
│ 커밋 / PR       ├──────────────────────────────────┤                  │
│ 최근 분석       │ 질문 입력창 / 분석 범위 표시       │                  │
└────────────────┴──────────────────────────────────┴──────────────────┘
```

데스크톱은 260px 왼쪽 탐색, 유동 폭 중앙 작업 영역, 300~340px 오른쪽 검사기를 사용한다. 중앙 본문은 읽기 편하도록 최대 폭을 제한한다. 1100px 아래에서는 검사기를 접을 수 있고, 760px 아래에서는 양쪽 영역을 서랍으로 전환한다.

## 4. 왼쪽 저장소 탐색

- 상단에 Code Atlas 이름과 `새 분석` 동작을 둔다.
- 저장소 검색과 등록된 저장소 목록을 제공한다.
- 저장소를 선택하면 `현재 변경`, `커밋`, `PR` 항목을 하위 탐색으로 표시한다.
- 최근 분석은 커밋 메시지 또는 PR 제목으로 표시하고 ref와 상태를 보조 정보로 둔다.
- OneDev 연결이 없는 저장소에서도 커밋과 로컬 소스 기능은 동일하게 동작한다.

기존 상단 탭과 왼쪽 저장소 카드 목록은 이 탐색 영역으로 합친다.

## 5. 중앙 분석 작업

중앙 영역은 카드 격자 대신 시간 순서의 이벤트 흐름으로 구성한다.

### 5.1 작업 머리글

- 커밋 메시지 또는 PR 제목
- 저장소명, 브랜치/ref, 짧은 OID
- `다시 분석`, `근거 검사기 열기` 동작
- 분석 중, 완료, 부분 해석, 실패 상태

### 5.2 이벤트 종류

1. `Git 스냅샷`: 변경 파일 수, 추가·삭제 줄 수, 분석 시점
2. `변경 스토리`: 왜 만들었나, 무엇을 바꿨나, 프로젝트 영향, 확인 경계
3. `영향 확인`: 변경 파일별 직접·역방향 관계와 미확인 연결
4. `질문`: 사용자가 입력한 질문
5. `답변`: 결론, 기록된 맥락, 코드 근거, 확인 필요, 다음 확인
6. `오류`: 실패 원인과 다시 실행할 수 있는 동작

변경 장부, 분석 범위와 diff는 해당 이벤트 안에서 펼치는 상세 영역으로 이동한다. 중요한 설명은 항상 펼쳐 두고 원문과 긴 diff만 접는다.

### 5.3 질문 입력창

- 중앙 하단에 유지되며 선택한 분석 범위를 함께 표시한다.
- 기본 문구는 `이 커밋이나 PR에 대해 질문하세요`다.
- 답변 생성 중에는 중복 전송을 막고 진행 상태를 같은 흐름에 표시한다.
- 질문과 답변은 저장된 분석 ID에 연결한다.

## 6. 오른쪽 근거 검사기

검사기는 Code Atlas만의 핵심 요소다. 중앙 설명을 읽는 흐름을 방해하지 않으면서 주장 근거를 즉시 검증하게 한다.

- `기록된 이유`: 커밋 제목·본문, PR 설명·댓글·리뷰
- `코드 변경`: 파일 경로, 상태, 추가·삭제 줄, diff
- `영향 관계`: 호출·import·route 등 분석된 정적 관계와 위치
- `확인 필요`: 분석하지 못한 파일, 동적 연결, 실행으로 검증해야 하는 항목

중앙 답변에서 근거 ID나 파일을 누르면 해당 검사 항목을 선택해 원문과 위치를 보여준다. 내부 UUID와 분석기 노드 ID는 사용자에게 노출하지 않는다. 파일 경로와 줄 번호를 기본 식별자로 사용한다.

## 7. 데이터와 컴포넌트

기존 API 응답을 화면 모델로 바꾸는 순수 변환 계층을 둔다.

```text
Scan + Report + Graph + Questions
                │
                ▼
        buildWorkspaceTimeline()
                │
      ┌─────────┴─────────┐
      ▼                   ▼
TimelineEvent[]      EvidenceGroup[]
```

주요 컴포넌트는 다음과 같이 분리한다.

- `AtlasWorkspace`: 저장소 선택과 전체 화면 상태
- `RepositorySidebar`: 저장소·커밋·PR 탐색
- `AnalysisThread`: 이벤트 흐름
- `SnapshotEvent`, `NarrativeEvent`, `ImpactEvent`, `QuestionEvent`
- `EvidenceInspector`: 근거 분류와 선택 상세
- `QuestionComposer`: 질문 입력과 전송 상태

현재 `Dashboard.tsx`가 가진 네트워크 호출과 표시 책임을 위 컴포넌트로 나눈다. API 호출은 별도 훅 또는 작은 클라이언트 모듈에서 관리한다.

## 8. 질문 이력

현재 DB에 저장되는 질문과 답변을 다시 읽을 수 있도록 저장소에 `listQuestions(scanId)`를 추가한다. `GET /api/scans/[id]`는 분석 결과와 질문 이력을 반환한다. 새 질문이 저장되면 중앙 흐름에 즉시 추가하고, 다시 접속할 때 저장된 순서로 복원한다.

질문 데이터에는 기존 `question`, `answer`, `created_at`만 사용한다. 대화 제목 생성, 사용자 계정, 멀티 세션 동기화는 이번 범위에 포함하지 않는다.

## 9. 시각 체계

- 배경: `#FFFFFF` 중앙 작업 영역
- 탐색: `#EEF3F7` 옅은 청회색
- 보조 영역: `#F8FAFC`
- 본문: `#20242B`
- 보조 글자: `#69717C`
- 선택·연결: `#3377E8`
- 확인 필요: `#C65D3A`

글꼴은 Windows와 웹에서 안정적인 `Segoe UI`, `Inter`, sans-serif 순서를 사용한다. 장식보다 행간, 최대 본문 폭과 정돈된 구분선을 우선한다. 기억 요소는 오른쪽 `근거 검사기`이며 관계 상태를 색 하나와 명확한 문구로 함께 표현한다.

## 10. 오류와 빈 상태

- 저장소 없음: 중앙에 저장소 경로 입력과 등록 동작 표시
- 변경 없음: 빈 결과로 숨기지 않고 기준 ref와 “변경 없음” 이벤트 표시
- LLM 실패: 정적 변경 스토리를 그대로 표시하고 해당 답변 이벤트에 실패 원인 표시
- OneDev 미설정: PR 영역에서 설정 방법 표시, Git 기능은 계속 사용 가능
- 부분 분석: 확인 필요 항목 수를 머리글과 검사기에 함께 표시

## 11. 접근성과 반응형

- 탐색, 검사기, 이벤트와 입력창은 의미 있는 HTML 영역과 제목을 사용한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다.
- 키보드 포커스를 항상 표시한다.
- 모바일 서랍은 열릴 때 초점을 이동하고 닫을 때 원래 버튼으로 돌려보낸다.
- `prefers-reduced-motion`에서 전환 애니메이션을 제거한다.
- 320px 폭에서도 질문 입력과 핵심 스토리를 읽을 수 있어야 한다.

## 12. 검증 기준

1. 저장소 선택부터 커밋 또는 PR 분석까지 기존 기능이 유지된다.
2. 분석 결과가 Git 스냅샷 → 변경 스토리 → 영향 확인 순서로 보인다.
3. 기록, 코드, 관계, 확인 필요 근거를 검사기에서 구분할 수 있다.
4. 근거 클릭 시 사용자용 경로와 줄 번호가 표시되고 내부 노드 ID는 보이지 않는다.
5. 저장된 질문과 답변이 새로고침 후 복원된다.
6. LLM이 없어도 전체 작업 흐름을 사용할 수 있다.
7. 데스크톱, 태블릿, 모바일 레이아웃에서 내용이 겹치거나 잘리지 않는다.
8. 전체 단위 테스트, 타입 검사와 프로덕션 빌드가 통과한다.

## 13. 구현 범위

이번 재설계에서 구현한다.

- Codex형 3영역 애플리케이션 셸
- 저장소·커밋·PR 통합 탐색
- 분석 이벤트 흐름
- 접을 수 있는 근거 검사기
- 하단 질문 입력창과 저장된 질문 이력
- 기존 분석 데이터의 화면 모델 변환
- 반응형·키보드 접근성

이번 재설계에서 제외한다.

- 소스 관계 지도
- GitHub/GitLab 전용 PR API
- 실시간 공동 편집
- 사용자 계정과 권한 시스템
- 코드 실행·테스트·배포 자동화
