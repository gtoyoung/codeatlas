# 설계 결정 기록

## 사용자 확인 내용

- 개발 인원은 2~4명이다.
- OneDev로 Git을 관리한다.
- Codex와 Claude를 활용한다.
- 개발 대상은 Next.js 기반 AI 솔루션이다.
- 개인의 프로그램 이해와 팀 간 작업 인수인계를 모두 지원해야 한다.
- 먼저 폴더와 Git 저장소를 만들고 상세 설계서를 작성한다.
- 대화 응답은 짧게 유지하고 상세 내용은 문서에 담는다.

## 설계 제안

| 결정 | 이유 | 재검토 조건 |
|---|---|---|
| 작업 카드를 중심 단위로 사용 | 여러 PR·담당자의 목적과 결과를 연결 | 실제 팀의 작업 단위가 다른 경우 |
| PostgreSQL에 그래프 관계 저장 | 초기 운영 구성 단순화 | 실제 경로 질의 성능·복잡성 증가 |
| React Flow는 관계 탐색 단계에 도입 | 인계 핵심 흐름을 먼저 검증 | 초기 파일럿에서 지도 부재가 사용을 막는 경우 |
| 별도 분석 워커 | 장시간 분석과 웹 요청 분리 | 배포 환경 제약 |
| 인계는 파일/API 계약부터 | AI 도구별 연동 차이 흡수 | 설치 환경에서 자동 연동 확인 |
| LLM 설명은 근거와 버전 필수 | 추정을 사실로 오인하는 문제 방지 | 원칙 유지 |
| 병합·배포·검증 상태 분리 | 현재 서비스 상태 오인 방지 | 원칙 유지 |
| 초기 자동 수정·배포 제외 | 이해와 인계 효과에 집중 | 후속 명시적 범위 변경 |

## 환경 확인 대기

OneDev 버전과 API, 실제 Next.js 저장소 구성, LLM API·반출 정책, Claude 사용 형태, 배포·로그인 환경을 확인한 뒤 구현 계획에서 확정한다. 개발 도구 구독만으로 서버 LLM API 권한이 제공된다고 가정하지 않는다.
