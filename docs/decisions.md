# 설계 결정 기록

## 사용자 확정 내용

- 2~4명 팀, OneDev Git 관리, Codex·Claude 사용, Next.js 기반 AI 솔루션.
- 개인 코드 이해와 팀원의 변경 이해를 함께 지원한다.
- Git 커밋과 로컬 소스만 분석 입력으로 사용한다.
- OneDev API·PR·리뷰 연동, Claude Code 인계 파일, 테스트 실행·배포 기록 수집은 제외한다.
- 상세 설계를 먼저 작성하며 대화 응답은 짧게 유지한다.

## 2026-09-13: v0.2 범위 정정

v0.1의 PR·작업 카드·외부 인계·검증 결과 중심 구조를 Git 변경·소스 스냅샷 중심으로 대체했다. 과거 설계는 Git 이력에 보존하며 이 범위는 v0.3에도 유지한다. 제외한 연동은 향후 예정 기능으로도 유지하지 않는다.

## 설계 제안

| 결정 | 이유 | 재검토 조건 |
|---|---|---|
| 로컬 분석을 첫 버전으로 | 기존 clone과 미커밋 소스를 직접 읽음 | 팀 공통 화면 필요 시 서버 clone 모드 추가 |
| 커밋·소스 스냅샷을 중심 단위로 | 별도 업무 입력 없이 근거 확보 | 원칙 유지 |
| PostgreSQL에 그래프 저장 | 초기 운영 구성 단순화 | 실제 그래프 질의 부담 증가 |
| React Flow 단계적 추가 | 변경 이해 흐름부터 검증 | 지도 필요성이 파일럿에서 확인될 때 |
| 별도 워커 | 웹 요청과 긴 분석 분리 | 실행 환경 제약 |
| LLM 근거·버전·추정 구분 | 코드만으로 알 수 없는 사실의 오인 방지 | 원칙 유지 |
| 확인 제안과 실행 검증 구분 | 테스트 소스는 실행 결과가 아님 | 원칙 유지 |

## 구현 전 확인

로컬 저장소 경로·OS·기준 브랜치, 실제 소스 구성, LLM API·전송 정책·예산을 확인한다. OneDev 업무 API·AI 인계 자동화·테스트/배포 시스템 연결은 요구하지 않는다.

## 2026-09-13: v0.3 리서치 기반 강화

현재 설계 기준은 v0.3이다. v0.2의 Git·로컬 소스 입력 범위를 유지하며 [리서치 근거](research-evidence.md)를 바탕으로 다음을 추가했다.

- 변경 장부와 파일·참조 처리 상태로 숨겨진 누락을 계수한다.
- 타입 분석·Next.js 버전별 규약·전후 그래프를 결합한다.
- UI 탐색 제한과 분석 엔진 예산을 분리한다.
- 기록된 의도·코드 변화·추정 이유를 구분한다.
- 문장별 근거의 위치뿐 아니라 지지 여부와 반례를 검사한다.
- 표본 precision·recall·설명 충족률을 별도 측정하며 전체 관계 완전성을 주장하지 않는다.

SCIP은 데이터 모델 참고이며 필수 서비스가 아니다. GraphDB는 계속 보류한다. 외부 인계·OneDev 업무 API·테스트/배포 기록 수집은 추가하지 않는다.

## 2026-09-13: 상세 구현 설계 추가

[상세 구현 설계서](implementation-design.md)에 모듈·데이터·실행 계약을 작성했다. 첫 수직 기능은 외부 패키지 없는 Git commit 장부 CLI이며, 이후 working_tree·DB·관계 분석·LLM·웹 순서로 확장한다. 단계 A는 ESM JavaScript로 Git 수집을 검증하고 B에서 TypeScript 기반 전체 실행 환경을 고정한다. 구현 코드는 아직 작성하지 않았다.
